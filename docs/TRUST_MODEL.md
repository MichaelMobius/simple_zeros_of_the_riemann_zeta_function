# Trust model

The final result has three distinct verification layers. Keeping these layers
separate makes the trust claims precise.

## 1. Mathematical / Lean statement

The endpoint `HurtadoZeta23.article_main_internal` is a closed theorem in the
local development: it does not receive `ArchivedSevenPointClaim` or an
Arb-generated proposition as an argument.

The audited local source tree contains no executable `sorry`, `admit`, new
mathematical `axiom`, `unsafe`, `extern`, `opaque`, or `implemented_by`
declaration.

## 2. Large finite computation

The formal development uses exact `Nat`, `Int`, and rational arithmetic for the
q60 certificate. Some large decidable statements are proved with
`native_decide`, including checks on multiplicities/tables and the complete
tree replay.

Therefore the present TCB is **not** described as “small-kernel-only
reduction.” It includes Lean's native evaluation mechanism in addition to the
Lean kernel and compiled environment.

The release should archive:

```text
audit/axiom-audit.txt
audit/build-log.txt
audit/BUILD_ENVIRONMENT.txt
```

generated by the compile-confirmed release workflow.

## 3. Arb/FLINT

The Arb/FLINT v1.2 artifact remains valuable as:

- provenance for rigorous transcendental bounds;
- an independently replayable proof-carrying certificate;
- an independent cross-check of the Lean/q60 route.

It is **not** an assumed proposition in the final Lean theorem.

## External dependencies

A complete release must pin:

- Lean `v4.33.0-rc2`;
- the exact upstream Zeta23 Git commit;
- the Lake dependency manifest / Mathlib revision resolved by that project.

The final release records these from the compile-confirmed environment rather
than inventing a replacement pin.
